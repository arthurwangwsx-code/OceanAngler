# 推进路线、资源与验收

| 阶段 | 交付与规模 | 出口 |
|---|---|---|
| F0 首批基础 | 产品/技术/美术/开源/发布方案、Unity工程、需求与任务、账号预检 | 文档/计划校验、Editor 导入、发布状态如实记录 |
| P0 钓鱼切片 | 1 海湾、3 原型鱼、2 钓组、完整捕获/积分/存档 | 20次连续循环、暂停恢复、真实 iPad/iPhone 可玩；模型仍 prototype |
| A0 美术样板 | 1 条英雄鱼、1 套钓具、1 处水上/水下环境 | 360°近景审阅、七语义动画、LOD、授权与真机预算 |
| P1 离线完整版本 | 3海域/12可钓鱼/3观察生物；6竿4轮4线6饵；18任务 | 全功能/无障碍/恢复/儿童试玩/20分钟性能与内容清单全通过 |
| P2 扩展 | 5海域/24鱼种、深海研究与观赏水族箱 | 另立需求，不阻碍P1 |

先 P0 再样板验收再批量内容，避免制作 12 条不达标模型。粗略工作量：基础与切片 1–2 工程周，美术样板 1–2 美术周，P1 工程 3–5 工程周、内容 4–8 美术周，整体验收 1–2 周；这是排期假设，非交付承诺。独立开发会串行增加日历时间，先以英雄鱼样板测实际产能。预算待样板原创/外包报价后决策，当前不购买资产。

关键依赖：Apple 已有身份及 API权限、可用内部测试账号、可创建应用记录；GitHub 身份与建库权限；Unity iOS模块与许可证；儿童试玩和目标最低真机；鱼类科学审核与资产许可。

风险：拟真模型成本高→英雄样板先验；水面透明耗时→质量档与预算；深海氛围吓人→明亮研究叙事；物种地域混杂→海域设定与科普核对；积分重复→结算幂等；开源资产授权→公开替代包；测试包误外发→内部专用导出与本人组审计。

## 验收与证据
每项分别记录实现和验收：PLANNED/IN_PROGRESS/IMPLEMENTED；NOT_RUN/PASS/PARTIAL/FAIL/BLOCKED。逻辑报告、Editor日志、模拟器截图、真机数据、资产转台、Apple回执独立保留。回滚为从已验证 master 创建 fix 分支或恢复上个签名测试 build，不改写历史。

F0 不要求所有 P1 玩法与成品模型完成。TestFlight 只有实际二进制可运行、签名通过、Apple处理完成且本人有测试权限才算可分发；安装回执缺失则实际安装仍 NOT_RUN。

## 下一次工作入口
先恢复本机Unity Licensing/Package Manager和网页控制连接，再运行tools/game.py prepare及tests。确认生成场景与五项规则实际通过后实现P0存档、3鱼/2钓组、中文触控UI，并完成英雄鱼样板。ASC应用记录创建后才导出iOS、签名和上传本人内部组。GitHub暂不远程公开：先恢复登录、核对目标仓库，再按开源清单发布。当前功能原型只有1条几何鱼和临时120积分，不满足P0内容/存档，不满足拟真美术。

iSpec续做：先检查product-technical-foundation真实状态，再恢复proposal/design/specs/tasks；不得把已有产品文档视为CLI状态已完成。
