# 连续钓鱼与自然解锁验证

目标对应REQ-01/02/03/06/07：通过真实GameUI控件连续完成20轮钓鱼，并核对逐轮持久化、自然积分解锁、装备选择、暂停返回、两档辅助和保护观察。该验证使用程序派发的Unity EventSystem事件；不能代替系统触摸、儿童试玩、最终美术或真机20分钟。

## 输入与边界

`RuntimeSmoke.RunJourney20`由PlayMode集成测试与原生Player共用。它不调用`FishingSession.Tick`、不注入积分或鱼获，不绕过锁定装备/海域；游戏通过正常`GameController.Update`推进。前10轮使用初学辅助，第11轮通过设置关闭辅助。每四轮通过钓具页选择当前已解锁的较强装备；每轮通过准备页选择自然解锁海域，优先尚未到访的海域。

每五轮在按住收线时打开图鉴，检查按住状态取消、暂停时张力和收鱼进度不动，返回后必须主动继续。每轮经抛投、咬钩、提竿、控线、收鱼和记录放流回到Ready；独立读取真实文件，检查条数、唯一catchId、released标志、积分合计与海域。每轮落盘RUNNING回执，失败或中断不能变成完整20轮PASS。

20轮后从图鉴完成三种保护生物的观察和记录，检查不增加鱼获/积分。PlayMode测试另重建Bay场景及GameController，验证20条记录、积分和3项观察恢复；这属于场景/控制器重建，不能称为操作系统进程重启。

必须显式指定新的隔离存档根目录，并要求初始鱼获/积分/观察为空且无主文件、备份或临时文件。既有玩家进度不用于本流程。原生输出目录须使用新标签；禁止复用覆盖回执。

## 执行

```sh
ispec changes measure --change product-technical-foundation --stage apply --category test -- python3 tools/game.py tests --test-platform PlayMode --label freshjourney --test-filter OceanAngler.Tests.ContinuousJourneyTests
```

`--test-filter`传给本机Unity Test Framework的`-testFilter`。不带该参数仍运行所选平台全量测试。每次使用新label保留隔离数据；原始日志和XML分别在运行后复制到本地证据目录，避免下一轮入口覆盖。

原生入口为`--ocean-journey20 <新输出目录> --ocean-save-root <新存档根目录>`，须先从包含此入口的源码重新构建。旧sim4没有该入口，不能借旧包宣称本轮通过。原生运行捕获实际游戏帧；无画面测试禁用截图并在回执标明无画面范围。两者必须分别执行、查看回执和实际原图后验收。

## 当前发现

首轮已记录命中失败后停止；等待滚动后布局更新仍未解决。第三轮的640×480实际Canvas/EventSystem诊断表明：“看看海湾”中心在(162.6,74)px、目标位于准备面板内且未被裁切，但最上层命中的是“结束本次 · 返回准备”。从钓具返回时世界保持暂停，底部返回按钮盖住准备面板的最后一行。

共享紧凑布局现根据暂停状态给准备面板预留底部空间，暂停时底边从36pt改为102pt，保持滚动内容在返回按钮上方。长流程点击滚动项前等待布局更新，并在首次命中失败时停止，不再用回调调用代替实际命中。当前验证结果以[连续流程报告](../reports/continuous-journey.md)为准；普通原生启动、模拟器会话与完整产品出口继续独立记录。

当前52项Editor与12项PlayMode通过，后者分为完整长流程1项及互不重叠的其余11项，避免重复统计。新增左右手回归均实际命中目标并进入观察。20轮、3项观察与场景重建通过；实际原生运行、系统触摸、儿童体验和美术仍未通过。
